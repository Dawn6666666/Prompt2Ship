## 为项目建立版本记录

在新项目根目录中执行一次：

```sh title="初始化版本库"
git init
```

保存第一版 `index.html` 后，先建立初稿提交：

```sh title="记录 v1 初稿"
git add index.html
git diff --staged
git commit -m "feat: add portfolio draft"
git log --oneline
```

**新文件尚未被 Git 跟踪时，普通 `git diff` 不会显示它。** 第一次用 `git diff --staged` 检查即将加入的内容；提交初稿后，再修改已跟踪的文件，才能看到 v1 到 v2 的差异。

已有项目通常已经包含 Git 记录，先用 `git status` 查看即可。

## 提交前，先检查范围

```sh title="查看当前状态与尚未暂存的改动"
git status --short
git diff
```

确认修改只涉及当前任务，运行检查后，只暂存相关文件：

```sh title="记录这一次修改"
git add index.html
git diff --staged
git commit -m "fix: adapt portfolio for mobile"
```

第一次提交时，Git 可能要求配置提交者姓名与邮箱。按终端提示设置你希望用于提交记录的身份。

## 想恢复时，先确认是哪种情况

| 情况                     | 操作含义                                                                   |
| ------------------------ | -------------------------------------------------------------------------- |
| 文件误放进暂存区         | `git restore --staged 文件名` 撤销暂存，保留工作区修改；需要已经有初始提交 |
| 未提交的文件修改不想保留 | 先查看并备份差异，再使用 `git restore 文件名`；它会丢弃该文件未暂存的修改  |
| 已提交的版本需要撤销     | 先查看 `git log --oneline`，再用 `git revert 提交号` 创建反向提交          |

可以先请 Agent 解释当前状态与恢复方案，确认要保留哪些修改后再执行。
