## 从一句想法开始补齐

<WorkflowScene client:load />

四项信息分别解决一个问题：

| 信息 | 示例                           |
| ---- | ------------------------------ |
| 目标 | 给潜在客户展示个人作品         |
| 内容 | 个人介绍、两个项目、邮件入口   |
| 范围 | 中文单页，这次不做登录和后台   |
| 验收 | 内容齐全，375px 下没有横向溢出 |

**已有项目还需要上下文。** 请 Agent 阅读相关文件，指出现有实现和改动位置；不要让它凭空创建另一套结构。

## 先看计划，再让代码生成

```text title="从需求进入计划"
根据以上需求，给出最小实现方案：
- 会创建或修改哪些文件？
- 按什么顺序实现？
- 用什么方式检查完成？
先给计划，等我确认后再写代码。
```

检查计划有没有增加不需要的功能、遗漏验收条件，或者重写原本可以沿用的部分。计划合理后，要求 Agent 按步骤实现，并汇报实际改动。

## 让一次修改保持清楚

一轮任务尽量只有一个可验证的目标。先让第一版能运行，再指出具体问题。新的想法可以记下来，避免在修复过程中不断扩大范围。
