# 07 · 演示工作台：布局、组件与联动

工作台是案例页的主体，替代现有 `CaseWorkbench.tsx` 与 `TodoLesson.tsx` 中各自实现的布局。两个案例和开工检查共用一套组件。

## 一、设计原则

1. **场景是主角**。读者应该首先看到“发生了什么变化”，说明文字只是旁白。
2. **一次只突出一个观察对象**。文件区、编辑区、终端、预览、Agent 面板都在，但当前步骤只有一个处于高亮，其他区域降低不透明度到 60%。
3. **读者控制节奏**。不自动播放；每个小步由读者点击“下一步”或直接操作场景推进。
4. **变化要看得见**。新文件、改动行、新版本、新输出出现时有 1 次短暂高亮（背景色淡入淡出 1.2s），不用持续闪烁。
5. **说的和做的分开**。Agent 回复区与文件/终端/预览在视觉上明确区分，配合四种状态色。

## 二、页面布局

### 2.1 桌面端（≥ 1024px）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 导航                                                                      │
├──────────────────────────────────────────────────────────────────────────┤
│ 案例一 · 个人主页        ① 想清楚 ② 定计划 ③ 生成并运行 ④ 发现问题 ⑤ 交付  [需求单] │ ← 步骤条，sticky
├───────────────────┬──────────────────────────────────────────────────────┤
│ 第 3 步 / 共 5 步  │  [● Agent 回复了]─[● 文件保存了]─[○ 跑起来了]─[○ 验证过了] │ ← 状态条
│ 生成并运行         │ ┌────────┬──────────────────────────┬──────────────┐ │
│                   │ │ 文件区  │ 编辑区 / 预览（标签切换）   │ Agent 面板   │ │
│ 这一步做什么       │ │        │                          │              │ │
│ 让文件真的出现…    │ │        │                          │              │ │
│                   │ │        ├──────────────────────────┤              │ │
│ 小步  a b ● d      │ │        │ 终端                      │              │ │
│ 当前：点击文件区   │ └────────┴──────────────────────────┴──────────────┘ │
│ 的 index.html     │                                                      │
│                   │                                                      │
│ 要点（≤3 条）      │                                                      │
│                   │                                                      │
│ 怎样算完成         │                                                      │
│ □ 我做到了         │                                                      │
│                   │                                                      │
│ [上一小步][下一小步]│                                                      │
├───────────────────┴──────────────────────────────────────────────────────┤
│ ← 定计划                                                   发现问题并修改 → │
└──────────────────────────────────────────────────────────────────────────┘
```

- 左栏固定 280px，sticky，内容超出时内部滚动；右侧场景占满剩余宽度，最大内容宽 1200px。
- 场景高度固定为 `min(640px, 视口高度 - 180px)`，避免页面在步骤间跳动。
- 仿 VS Code 窗口的分区可按步骤配置显示哪些区域：第 1 步只显示需求拆解器（不显示 VS Code）；第 2 步突出 Agent 面板；第 3 步四区全显；第 4 步预览放大。
- 步骤条：5 个步骤等宽但整体最大宽度 720px 居中，不再拉满 1320px。完成的步骤显示 ✓（只在读者勾选“我做到了”后）。

### 2.2 平板（640–1023px）

- 左栏变为场景上方的一条折叠说明（显示标题 + “这一步做什么”，点开查看要点）。
- 场景中 Agent 面板变为编辑区的一个标签。

### 2.3 手机（< 640px）

```
┌──────────────────────────────┐
│ 案例一  ③ 生成并运行  3/5  ▾ │ ← 点开为步骤列表（抽屉）
├──────────────────────────────┤
│ 让文件真的出现，再让网页打开   │ ← 一句话
├──────────────────────────────┤
│ [文件][代码][终端][预览][Agent]│ ← 观察对象标签，当前对象自动选中
│ ┌──────────────────────────┐ │
│ │       场景（全宽）         │ │
│ └──────────────────────────┘ │
│ 当前：点击 index.html          │
│ [上一小步]        [下一小步]   │
├──────────────────────────────┤
│ ▸ 要点                        │ ← 折叠
│ ▸ 怎样算完成                  │
└──────────────────────────────┘
```

- **场景先于说明**，首屏能看到当前观察对象。
- 每个小步配置一个“主要观察对象”，切到该小步时自动切换到对应标签，标签上有圆点提示“这里有变化”。
- 步骤条不横向滚动，改为下拉抽屉；去掉可见滚动条。
- 代码区字号 13px，允许横向滚动；预览 iframe 按实际 375px 显示，不缩放。

## 四、联动规范

联动通过一个场景状态对象驱动，而不是组件之间直接调用：

```ts
type SceneState = {
  step: number;            // 1-5
  substep: string;         // 'a' | 'b' ...
  focus: 'files' | 'editor' | 'terminal' | 'preview' | 'agent' | 'brief';
  files: FileEntry[];      // 含 status: 'new' | 'modified' | 'planned' | 'clean'
  openFile?: string;
  highlight?: { file?: string; lines?: [number, number]; region?: string; briefRow?: string };
  previewVersion: 'v1' | 'v2';
  previewWidth: number;
  commits: Commit[];
  status: { replied: boolean; saved: boolean; running: boolean; verified: boolean };
};
```

每个小步在数据文件中声明为对 `SceneState` 的变更（patch），工作台按顺序应用。这样文案作者可以只改数据文件。

必须实现的联动：

| 触发 | 联动结果 |
|---|---|
| 终端执行 `pwd` | 输出路径与文件区标题同色高亮 |
| Agent 创建/修改文件 | 文件区出现标记 → 读者点击 → 编辑区打开并高亮变化行 |
| 终端输出本地地址 | 地址可点击 → 预览打开，两者之间连线动画一次 |
| 点击 Agent 回复中的某条修改 | Diff 对应行 + 预览对应区域同时高亮 |
| 点击检查项的“怎么检查” | 场景切到对应视图（例如预览切 375） |
| 切换 v1/v2 | 保留预览宽度和滚动位置 |
| 计划条目 / 问题现象 | 需求单抽屉打开并高亮对应行（绿=符合、红=冲突/未达到） |
| 文件区点击“将修改”文件（案例二） | Agent 计划中对应说明高亮 |

## 五、四种状态的视觉

| 状态 | 颜色令牌 | 图标 | 出现位置 |
|---|---|---|---|
| Agent 回复了 | `--state-reply`（紫） | 对话气泡 | Agent 面板、状态条 |
| 文件保存了 | `--state-saved`（蓝） | 文件 | 文件区标记、状态条 |
| 程序跑起来了 | `--state-running`（绿） | 播放 | 终端地址、预览边框、状态条 |
| 结果验证过了 | `--state-verified`（深绿） | 盾牌勾 | 检查清单、状态条 |

- 状态条未点亮时为灰色描边；点亮时填充颜色并有一次 300ms 缩放。
- 状态条悬停/点击显示一句解释，如“文件保存了：文件真的写进了文件夹，不只是出现在对话里。”

## 六、“示例结果”与“我做到了”

全站统一的底部组件 `DoneCheck`：

```
怎样算完成
  文件区出现 index.html，浏览器打开 localhost:3000 能看到页面。

  演示中的结果   ✓ 文件已创建  ✓ 页面已打开            ← 灰底小标签“示例”
  在你的电脑上   [ ] 我做到了
```

- 演示播放完不会自动勾选“我做到了”。
- “我做到了”只存在本机浏览器，用于进度显示；没有任何上传。
- 第一次出现时附一句说明：“这个网站不会读取你电脑上的任何东西，所以需要你自己确认。”之后不再重复。

## 七、无障碍与可用性

- 所有可点击区域有可见焦点环；场景内元素可用 Tab 键遍历，`←/→` 切换小步。
- 高亮不仅靠颜色：同时有边框或图标。
- 动画遵守 `prefers-reduced-motion`：关闭位移和连线动画，保留颜色变化。
- 代码与命令都有复制按钮，复制后按钮文字变为“已复制” 1.5s。
- iframe 预览有 `title`，读者可在新标签页打开真实 HTML。
