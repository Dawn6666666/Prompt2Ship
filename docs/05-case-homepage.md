# 05 · 案例一：个人主页（从零开始）

## 概要

| 项 | 内容 |
|---|---|
| 路由 | `/case/homepage/` |
| 起点 | 开工检查完成：空的 `my-homepage` 文件夹 + Git 仓库 + 能回话的 Agent |
| 终点 | 一个 `index.html` + `需求单.md` + 两个 Git 版本（v1 初稿、v2 修好手机端） |
| 人物 | 周小满，大一下学期，计算机类专业，想做一个主页附在实习/夏令营申请里 |
| 页面内容 | 名字 + 一句介绍；两个项目（C 语言课程大作业“成绩管理小工具”、社团招新海报网页）；邮箱 `xiaoman@example.com` |
| 运行方式 | `npx serve .`（地址 `http://localhost:3000`） |
| 核心情节 | 电脑上看起来正常 → 换成手机宽度出现横向滚动条 → 回到需求单确认这是缺陷 → 描述可复现的问题 → Agent 只改样式 → 对照代码与效果 → 提交 v2 |

> 人物、项目、邮箱都写成占位并在交付时提示替换。所有页面内容在 `data/homepage.ts` 中集中维护。

---

## 第 1 步 · 想清楚

**这一步做什么**：把“帮我做个个人网站”变成一份能检查的需求单。
**怎样算完成**：需求单五问都有回答，“怎样算做完”至少有两条能检查的标准。

- 主体交互：需求拆解器，完整设计见 `03-requirements-analysis.md` 第二节。
- 场景：桌面端左边是五问卡片，右边是需求单实时预览；不出现 VS Code 窗口（这一步还没有动手）。
- 结束时：复制提示词；建议保存为 `需求单.md`。

## 第 2 步 · 定计划

**这一步做什么**：让 Agent 先说打算怎么做，你检查后再让它动手。
**怎样算完成**：计划里的每一条都能对应到需求单，冲突的地方已经改掉。

场景（仿 VS Code，Agent 面板为主角）：

1. 读者的提示词出现在 Agent 面板。
2. Agent 回复一份计划（预设）：

```
我的计划：
1. 创建 index.html，包含页头（名字、介绍）、项目区（两张卡片）、联系区（邮箱）
2. 使用 Tailwind CSS（通过 CDN 引入）来写样式        ← 与需求单冲突
3. 头像使用灰色圆形占位
4. 配色方案 A：白底深蓝；方案 B：米色底墨绿
需要你补充：两个项目的链接
```

3. 场景右侧的需求单抽屉自动打开，计划第 1、3、4 条与需求单对应行连线（绿色），第 2 条与“不用框架”连线（红色）。
4. 读者点击“回复 Agent”，出现示范回复：

```
不要用 Tailwind，只写原生 CSS，放在 index.html 的 <style> 里。
配色用方案 A。项目链接先用 # 占位。
其他按计划进行，可以开始创建文件了。
```

5. 文件区此时**仍然为空**，旁边标注：“到目前为止 Agent 只说了话，还没有创建任何文件。”

教学要点（左侧说明栏，最多三条）：

- 计划是用来检查的，不是用来读一遍就放过的。
- 冲突的地方当场说清楚，比生成后再改便宜得多。
- 让 Agent 列出“需要你补充的信息”，可以避免它编造内容。

## 第 3 步 · 生成并运行

**这一步做什么**：让文件真的出现在文件夹里，再让网页在浏览器里打开。
**怎样算完成**：文件区有 `index.html`；浏览器打开 `localhost:3000` 能看到页面；Git 有了第一个版本。

这一步是“四种状态”第一次完整出现的地方，场景分四个小步，状态条在场景顶部依次点亮：

```
[● Agent 回复了] ─ [● 文件保存了] ─ [○ 程序跑起来了] ─ [○ 结果验证过了]
```

| 小步 | 读者操作 | 场景变化 | 状态条 |
|---|---|---|---|
| a | 点击“发送” | Agent 面板显示“正在创建 index.html…”，然后显示“已创建 index.html（86 行）” | Agent 回复了 |
| b | 点击文件区的 `index.html` | 文件区出现 `index.html`（新文件标绿点），编辑区打开代码，代码按区块（页头/项目/联系/样式）用浅色背景分组；点击右侧“页面结构”中的区块名，代码定位到对应行 | 文件保存了 |
| c | 复制并“运行” `npx serve .` | 终端输出 `Serving! Local: http://localhost:3000`，地址被高亮；点击地址，预览面板打开，地址与预览之间出现连线动画 | 程序跑起来了 |
| d | 复制并“运行” `git add .`、`git commit -m "v1 初稿"` | 版本记录出现 `v1 初稿`；文件区 `index.html` 的绿点消失 | — |

- 小步 b 后加一句提示：“如果 Agent 只是把代码贴在对话里，而文件区没有出现文件，说明文件没有保存。这时要让它‘把代码写入 index.html’，或者自己新建文件粘贴。”——用一张折叠的示例对比说明。
- 小步 c 解释文件、服务器、浏览器的关系，用一张三格小图：`index.html（文件）→ serve（把文件交给浏览器的小程序）→ 浏览器（显示结果）`。说明“关掉终端，网页就打不开了”。
- 第 4 个状态“结果验证过了”此时保持未点亮，并标注：“页面能打开，不等于做完了。第 5 步会逐条检查。”

## 第 4 步 · 发现问题并修改

**这一步做什么**：在手机宽度下发现问题，描述清楚，让 Agent 只改相关代码。
**怎样算完成**：手机宽度下没有横向滚动条；修改只涉及样式。

场景以**预览面板**为主角：

1. 预览默认是电脑宽度，页面正常。顶部有宽度切换：`手机 375` / `平板 768` / `电脑 1280`，以及可拖动的宽度条。
2. 读者切换到手机：页面右侧被截断，底部出现横向滚动条，标题换行难看。场景用红色虚线框标出超出部分。
3. 需求单中“没有横向滚动条”一行闪烁，说明：“这条是第 1 步写下的验收标准，现在没达到——这是缺陷，不是新需求。”
4. **反馈练习**：给出三种反馈，读者选择最好的一种：

| 反馈 | 评价 |
|---|---|
| “手机上不好看，改一下” | 看不出哪里有问题，Agent 只能重写 |
| “把整个页面改成响应式” | 范围太大，可能动到你满意的部分 |
| “在 375px 宽度下页面出现横向滚动条，项目卡片被截断。请只修改 CSS，让页面在手机上单列显示，不要改动文字内容和电脑端效果。” | ✓ 有宽度、有现象、有范围、有不能动的部分 |

   好反馈的四个要素用下划线标出：**在哪里**（375px）、**看到什么**（横向滚动条、卡片被截断）、**改什么**（只改 CSS，单列）、**不要动什么**（文字内容、电脑端）。

5. 读者发送好反馈后，Agent 回复修改说明（预设，三条：去掉固定宽度 `width:760px` 改为 `max-width`；标题字号用 `clamp`；560px 以下项目区单列）。
6. 编辑区出现 Diff 视图，只有 `<style>` 中的几行变化。点击回复中的任一条，Diff 中对应行和预览中对应区域同时高亮。
7. 预览可切换“修改前 / 修改后”，**保持当前宽度和滚动位置**。

左侧说明栏教学要点：

- 先对照需求单判断：这是缺陷还是新想法？
- 好反馈 = 在哪里 + 看到什么 + 改什么 + 不要动什么。
- 让 Agent 改完后说明“改了哪几处”，方便你检查。

## 第 5 步 · 检查并交付

**这一步做什么**：逐条对照需求单检查，看清这次改了什么，提交版本，交付文件。
**怎样算完成**：检查清单全部通过；Git 里有 v1、v2；拿到 HTML 和替换清单。

### 5a 逐条检查

清单由需求单自动生成，每一项有三列：

| 检查项（来自需求单） | 怎么检查 | 示例结果 |
|---|---|---|
| 有名字和一句介绍 | 看页面顶部 | ✓ 通过 |
| 有两个项目 | 数一下项目卡片 | ✓ 通过 |
| 邮箱链接能点 | 点击邮箱，看是否打开邮件应用 | ✓ 通过 |
| 电脑上完整显示 | 预览切到 1280 | ✓ 通过 |
| 手机上没有横向滚动条 | 预览切到 375，左右拖一下 | ✓ 通过（v1 未通过） |
| 只用了一个 index.html，没有框架 | 看文件区和代码开头 | ✓ 通过 |

- 点击“怎么检查”会把场景切到对应视图（例如自动把预览切到 375）。
- “示例结果”列是演示数据，表头灰色标注；每行右侧另有读者自己的勾选框“我检查过了”。

### 5b 看清改了什么

- Git 场景：`git diff` 的真实输出（v1 → v2），旁边一句话总结“只改了 `<style>` 里的 9 行，HTML 内容没有变”。
- 读者操作：`git add .`、`git commit -m "v2 修复手机端横向溢出"`；版本记录出现 v2。
- 点击 v1 / v2 可在预览中切换版本（保持宽度）。
- 提示：“以后改坏了，可以回到任何一个版本。”只提一句，不展开 `git checkout`。

### 5c 交付

交付卡片：

```
你的个人主页已经完成
────────────────────────────────────────
📄 index.html                [下载]
📄 需求单.md                  [下载]

替换清单（交出去之前要改的）：
[ ] 名字和介绍换成你自己的
[ ] 两个项目换成你做过的，并补上链接
[ ] 邮箱换成你的
[ ] 头像占位换成你的照片（可选）

怎么打开：在文件夹里运行 npx serve . ，浏览器访问 localhost:3000
下一步可以做什么：发布到网上（链接到 GitHub Pages 说明）/ 继续案例二
```

案例末尾一个简短回顾：五步各一句话 + 这次的四个状态是在哪一步点亮的。不超过一屏。
