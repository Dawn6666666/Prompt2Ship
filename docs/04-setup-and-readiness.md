# 04 · 准备篇：安装、连接与开工检查

准备篇的目标：**读者结束时拥有一个能用的工作台，并且亲眼确认过每一件工具都能工作。**
它不是完整安装手册；遇到复杂情况时链接到官方文档。

## 一、总览页 `/start/`

- 一张四项清单，每项一行：图标、名称、预计时间、状态（未开始 / 我做到了）。

```
准备工作台                                      已完成 1 / 4
────────────────────────────────────────────────────────────
✓  安装 VS Code            写代码的地方           10 分钟
○  安装 Node 和 Git        让网页跑起来、保存版本   10 分钟
○  安装并连接 Agent        和你一起写代码的 AI     10 分钟
○  开工检查                确认它们能一起工作       5 分钟
```

- 页首一句话说明“为什么要装这些”：VS Code 是工作的地方，Node 用来运行网页，Git 用来保存每一个版本，Agent 是帮你写代码的助手。
- 页首有系统选择（Windows / macOS），选择后全站命令与截图跟随切换。Linux 合并进 macOS 说明中的“Linux 用户”折叠段。

## 二、单页统一结构

每一页（编辑器 / 工具 / Agent / 开工检查）使用相同的四段结构：

1. **这一步完成后你会有什么**（一句话 + 一张最终状态的截图）
2. **步骤**（编号列表，每步一个动作；命令用可复制代码块；需要看界面的步骤配真实截图）
3. **怎么确认做好了**（具体到“看到什么”；示例输出与“我做到了”勾选分开）
4. **遇到问题**（折叠的 3–5 条常见问题，每条一句原因 + 一句解决办法）

页面右侧（桌面）放一个小型“认识界面”演示，如 VS Code 四区域高亮；手机端放到步骤之后。

## 三、安装 VS Code `/start/editor/`

- 保留 EditorTour 的真实截图，删除仿真窗口与截图重复的部分，只保留一个组件：**VS Code 界面地图**。
- 四个区域：文件区（资源管理器）、编辑区、终端、Agent 区（侧边栏/扩展面板，或终端里的 Agent）。点击区域名称，截图上对应区域高亮并出现一句说明。
- 文件夹名统一为 `my-homepage`（截图需要重新拍摄或使用统一的仿真界面）。
- 必须讲到的操作：如何打开一个文件夹（文件 → 打开文件夹）、如何打开集成终端（`` Ctrl+` ``）。
- 建议安装中文语言包，但所有截图按英文界面菜单名附中文注释（如 “Terminal（终端）”），避免语言不同导致读者找不到。

## 四、安装 Node 和 Git `/start/tools/`

- 删除 Python。案例一运行使用 `npx serve .`。
- 只做两件事：安装，检查版本。

```bash
node -v      # 看到 v20 或更高
git -v       # 看到 git version 2.x
```

- Git 首次使用需配置姓名与邮箱，放在这一页：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

- 演示组件：一个终端，点击每条命令显示示例输出，输出中的版本号被标注“看这里”。失败输出（`command not found` / `不是内部或外部命令`）作为第二个标签页展示，配一句解决办法（“重新打开 VS Code 让它读到新的环境变量”）。

## 五、安装并连接 Agent `/start/agent/`

- 保留多工具选择，但**默认推荐一个工具**，并在页首说明理由（免费额度 / 国内可用 / 与教程截图一致等，由团队定稿）。其他工具折叠为“使用其他工具”，只给出官方安装链接和连接方式的要点。
- 三步：安装 → 连接模型 → 第一次对话。
- 连接模型是新手最容易卡住的地方，单独给出：
  - 什么是 API Key（一句话），去哪里获取，不要把 Key 发给别人或写进代码；
  - 连接成功的样子（截图或示例输出）；
  - 常见失败：额度不足、网络、Key 复制不全。
- 第一次对话使用**只读任务**：

```
你好，请用一句话介绍你能帮我做什么。先不要创建或修改任何文件。
```

- 说明 Agent 可以在两种地方运行：VS Code 集成终端（命令行 Agent）或 VS Code 扩展面板（插件 Agent）。用一张两栏小图说明，不把“安装插件”作为共同前提。
- **核实所有安装命令**：现有数据中 mac/Linux 的 `npm install -g @opencode/cli` 等命令需要对照官方文档逐一核对后再上线，文档中记录核对日期。

## 六、开工检查 `/start/check/`（吸收提纲第一部分）

标题：**开工检查：确认工具能一起工作**。共 5 个检查，以演示组件串成一个连续场景（同一个仿 VS Code 窗口，状态逐步累积）。

| # | 做什么 | 读者操作（可复制） | 场景里的变化 | 怎样算完成 |
|---|---|---|---|---|
| 1 | 建一个空文件夹 | 在桌面或文档里新建 `my-homepage` | 系统文件夹窗口出现 `my-homepage` | 知道项目放在哪 |
| 2 | 用 VS Code 打开它 | 文件 → 打开文件夹 → `my-homepage` | VS Code 标题栏显示 `my-homepage`，文件区为空 | 文件区顶部显示 `MY-HOMEPAGE` |
| 3 | 打开终端，确认位置 | `` Ctrl+` `` 打开终端，输入 `pwd`（Windows：`cd`） | 终端出现，输出路径以 `my-homepage` 结尾，路径与文件区标题被同一颜色连线 | 终端路径的最后一段是 `my-homepage` |
| 4 | 初始化 Git | `git init` | 仓库状态从“未初始化”变为“已初始化，还没有任何版本”；文件区可展开查看隐藏的 `.git`（解释：Git 的记录本，不要手动改） | 输出 `Initialized empty Git repository` |
| 5 | 让 Agent 看一眼 | 在 Agent 中发送：`看看当前文件夹里有什么，用一句话告诉我。不要创建或修改文件。` | Agent 回复“当前文件夹是空的，只有 Git 仓库”；文件区**没有变化**（显式标注“文件区没有新文件——它只是看了，没有动手”） | Agent 正确说出文件夹是空的 |

说明：

- 用“建文件夹 → VS Code 打开 → 集成终端”的顺序，让后面所有命令都在一个窗口完成；不使用 `mkdir`/`cd` 作为必经步骤（新手在系统终端和 VS Code 终端之间切换容易迷失目录），`mkdir` 方式作为“习惯命令行的同学”的折叠备选。
- 检查 5 同时为案例一埋下伏笔：**Agent 回复了，但文件没有变**——这就是“回复”和“保存”的区别。
- 页面底部：

```
示例结果：5 项检查都通过（这是演示）
我做到了：[ ] 我在自己的电脑上完成了这 5 项
                                          [ 进入案例一 → ]
```

- 运行环境（Node）的检查已经在 `/start/tools/` 做过，这里不重复，只在“遇到问题”中链接回去。
