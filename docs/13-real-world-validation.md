## 一、招募与环境

招募 3–5 位目标同学，记录其编程经验、Agent 使用经验、操作系统、是否已经安装工具；不记录姓名、API Key、账号密码或支付信息。至少 3 人必须在自己的电脑上完成从空文件夹开始的个人主页案例。Windows 与 macOS 尽量各覆盖一人；未覆盖的系统明确写“未验证”。

每人安排约 60–90 分钟，可分为准备与案例两次。安装受网络影响的等待单独计时，不混入需求分析用时。提前说明可能产生模型费用，参与者自行确认账号和额度，不替参与者登录或复制密钥。

观察员不提前讲解页面答案，不替参与者点击。遇到阻塞先问“你现在想做什么、准备在哪输入”；必要时提供帮助并记录次数、位置和内容。网站中的“我做到了”由参与者自行勾选。

## 二、任务与成功依据

| 任务           | 做法                                                                      | 记录与阈值                                                                                 |
| -------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 准备工作台     | 按准备篇完成安装、连接、空目录、Git 与只读检查                            | 记录错输位置、目录混淆、系统差异；能指出 Shell、Agent 交互命令和自然语言的区别             |
| 看懂需求分析   | 完成案例一的五问与验收判断，不提示正确答案                                | 合上网页后能说出五问中的至少四问                                                           |
| 迁移到新题目   | 给出“帮我做个记账网页”，使用空白模板，不复制个人主页示例                  | 10 分钟内写出用途、必须有、这次不做、至少两条可重复检查的完成标准和不确定项                |
| 在本机完成案例 | 从空的 `my-homepage` 开始生成、保存、运行、复现与修复手机溢出，提交 v1/v2 | 至少 3 人得到可运行 HTML 和真实 Git 记录；每人流程性求助不超过 2 次。单独记录安装/账号问题 |
| 解释四种状态   | 指出 Agent 回复、磁盘文件、本地地址、验收依据                             | 能解释“回复了”不等于“保存了”，并实际找到 `index.html`                                      |
| 给具体反馈     | 先选择页面中的反馈，再独立描述一次缺陷                                    | 包含环境/操作、实际现象、期望结果、修改边界；能用 Diff 说明改了什么                        |
| 阅读已有项目   | 完成 Todo 文件地图与备注缺陷场景                                          | 能指出请求、接口、数据库的职责，解释未传 notes 与主动清空的区别                            |
| 找回学习位置   | 离开案例并返回首页，再打开需求单与速查                                    | 找到继续入口；知道浏览位置不代表本机完成记录                                               |

未达到阈值时记录具体失败，不把“基本完成”“看起来理解了”写成通过。3–5 人只能发现明显阻塞，不能据此声称课程对所有初学者有效。

## 四、真实 VS Code 截图清单

这些是**待采集素材**，不能拿网站的仿真界面截图冒充。只有确认能够操作真实编辑器时再执行。

1. 新建并打开空的 `my-homepage`：标题与文件区能识别目录，尚无 HTML。
2. 界面地图：英文菜单名附中文注释，标出文件区、编辑区、集成终端、Agent 入口。终端型与扩展型 Agent 分别说明，不暗示必须安装插件。
3. 确认路径与初始化 Git：`pwd` / `Get-Location` 的当前目录、`git init` 与 `git status`，说明 `.git` 是记录目录。
4. 只读 Agent 回复：同一工作区，无新增网页文件；遮盖账号、提供商标识中的个人信息与密钥。
5. 文件保存并运行：`index.html`、服务器 Local 地址、浏览器页面，能够建立三者关系。

建议目录为 `public/images/setup/`，文件名如 `vscode-windows-workspace.png`、`vscode-macos-terminal.png`；只添加实际拍摄的文件。采集时填写清单：系统、VS Code/Agent 版本、日期、对应步骤、替代文字、隐私检查人。

素材遵守 12px 圆角、1px 边框、无装饰阴影；标注用数字与蓝色边框，不只靠颜色。手机上文字不可读时提供原图入口，而不是继续缩小。未采集系统使用明确标注的交互地图，不复用另一系统截图冒充。

## 五、回填与复测

把问题分为“阻塞跟做 / 理解错误 / 可用性打磨”，优先修复命令输入位置、目录、费用与授权误解。保留失败记录；修复后重做相同任务，区分首次与复测结果。真实照片和学生测试分别满足条件后，才能勾选路线图的对应项目，并在 `11-implementation.md` 记录证据位置与日期。
