# 02 · 信息架构与学习路线

## 一、学习路线：三段、一条线

```
准备（约 30 分钟）          案例一：个人主页（约 60 分钟）        案例二：给 Todo 加备注（约 60 分钟）
─────────────────          ────────────────────────────          ────────────────────────────
① 安装 VS Code              ① 想清楚：把一句话变成需求单           ① 想清楚：先读懂现有项目
② 安装 Node 和 Git          ② 定计划：先让 Agent 说怎么做          ② 定计划：确认要改哪几个文件
③ 安装并连接 Agent          ③ 生成并运行：文件出现，网页打开       ③ 生成并运行：改动地图 + 运行
④ 开工检查                  ④ 发现问题并修改：手机端溢出           ④ 发现问题并修改：勾选完成后备注被清空
                            ⑤ 检查并交付：对照需求单、提交版本     ⑤ 检查并交付：只改了该改的
```

- 两个案例使用**同一套五步**，第二遍是对第一遍的强化。读者做完案例二时，五步已经形成习惯。
- 准备篇的“开工检查”就是案例一的起点：检查完成时，读者已经有一个空的 `my-homepage` 文件夹、Git 仓库和能回话的 Agent。
- 每一步的第一项都是“想清楚”，这是全站反复强调的主线。

### 五步的统一名称（全站只用这五个词）

| # | 名称 | 一句话 | 对应状态色 |
|---|---|---|---|
| 1 | 想清楚 | 把模糊的想法变成能检查的需求单 | — |
| 2 | 定计划 | 让 Agent 先说打算怎么做，你确认后再动手 | Agent 回复（紫） |
| 3 | 生成并运行 | 文件真的被保存，程序真的跑起来 | 文件保存（蓝）→ 正在运行（绿） |
| 4 | 发现问题并修改 | 用可复现的描述反馈，让 Agent 只改相关部分 | Agent 回复 → 文件保存 |
| 5 | 检查并交付 | 逐条对照需求单，提交版本，交付文件 | 已验证（深绿） |

## 五、进度与续读

- 进度保存在 `localStorage`，只记录**读者自己勾选的“我做到了”**，不记录“看过”。
- 导航和准备总览页显示进度；首页主按钮在有进度时变为“继续：案例一 · 第 3 步”。
- 提供“清除进度”入口，放在速查页底部。
