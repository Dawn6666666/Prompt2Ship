## 三、工程实现与合理调整

1. **场景状态**：数据补丁管理步骤与小步；文件标记、四状态、提交记录和高亮由 `sceneArtifacts` 派生，而不是保存成多份独立可变状态，避免倒退时残留。场景渲染仍是 React 组件，不宣称任意新教学场景只改 JSON 就能生成。
2. **组件样式**：全局 `base.css` 只留重置与排版，少于 200 行；站点与工作台的类作用域样式移到对应组件目录。不为这次重构再次改用一套 CSS 框架或机械转换为 CSS Modules。样式检查覆盖 `src/**/*.css`。
3. **设计约束**：六级字号、状态背景、间距令牌已补齐；构建检查基础样式体积、令牌、禁用文案、目录/命令一致性、真实 HTML 来源与内外证据同步。源码检查不是对任意外部内容或真实学习效果的证明。
4. **预设案例边界**：学生自己的需求草稿用于练习与导出；后续仍使用明确标注的固定案例，固定案例的需求与验收共用同一份行映射。不引入实时 AI，也不假装能自动判断任意自定义需求写得好不好。
5. **焦点与联动**：引用行在场景中直接显示，读者点击再打开需求抽屉；不在每次小步变化时强行打开模态抽屉抢走键盘焦点。本地地址到预览使用一次短高亮说明连接，不绘制易遮挡内容的跨区域长连线。
6. **布局**：保留窄侧栏、场景优先和自适应高度；未强制所有场景等高，也不对长需求单增加多层内部滚动。375px 原尺寸，桌面缩略图仅看布局，阅读代码或文字可用原尺寸或独立页面。
7. **节奏与工具**：首页演示由读者控制，不增加自动播放；安装采用已验证的 Node 24 LTS；Git 身份用项目级配置而非修改全局。应用交付仍是一份 HTML，需求单是单独的教学文档。
8. **兼容跳转**：支持 `_redirects` 的平台使用 301，Vercel 使用永久 308，其他纯静态托管使用 HTML 跳转；没有把静态页面跳转伪称为任何平台上的 HTTP 301。
